# Harness

Installed by the kit (`/arnes`, or `harness-install.sh <project>`). Re-running it updates the managed files
(marked `kit-harness: managed file`) and never touches a file without that mark.

## Verification: the evidence that a task is done

| Command | What it runs | Needs |
|---|---|---|
| `bash scripts/verify.sh` | Go: gofmt, `go vet`, golangci-lint, `go test ./...` · Front: npm `typecheck`, `lint`, `test` | nothing running |
| `bash scripts/verify.sh --full` | the above + the Postgres integration harness | `docker compose up -d`, goose |

It checks one Go module (`backend/` or the repo root) and one front (`frontend/`, or a root `package.json` that
depends on vue); other modules of a `go.work` are not covered. It ends with `verify: PASS|FAIL (...)` and exits
non-zero on failure. An optional step that cannot run (golangci-lint or an npm script missing) is listed as
`SKIPPED`: a PASS with skipped steps is weaker evidence, say so when reporting. Missing go/node, a front without
`node_modules` and a run where no test ran at all are failures, not skips. Each step gets `VERIFY_TIMEOUT`
seconds (default 900). `make verify` / `make verify-full` are aliases when the kit created the root Makefile
(created once, yours to edit).

## Integration harness (Go + Postgres projects)

`scripts/test-integration.sh` in the Go module (`make test-integration` there) creates a throwaway database
`app_test_<epoch>_<pid>`, applies `db/migrations` with goose, runs `go test -tags=integration ./...` and drops the
database on exit (also on Ctrl-C; leftovers older than an hour are swept on the next run).

- Tests carry `//go:build integration`; the fast verification needs no Docker.
- `testutil.NewPool(t)` reads `DATABASE_URL_TEST` and refuses any database not named `*_test_<n>_<n>` or not on localhost.
- Fixtures: `internal/testutil/fixtures/*.sql`, loaded with `testutil.Load(t, pool, "name")`; keep them idempotent.
- Other port, credentials, compose file or service name: `HARNESS_PG_URL=postgres://user:pass@localhost:5433`,
  `HARNESS_COMPOSE=path/compose.yml`, `HARNESS_PG_SERVICE=db`. Development credentials only.
- When `go.sum` lacks the harness dependencies the run executes `go mod tidy`; commit `go.mod` and `go.sum` after it. `-race` is used only when CGO is enabled.

## API contract (projects generated by the kit)

`backend/cmd/api/contract_test.go` runs in the fast verification: every GET in `api/openapi.yaml` must be a
registered route, and GETs without path parameters must answer with a declared status. The parser accepts
block-style YAML with 2-space indentation only and fails loudly otherwise.

Out of scope: browser e2e, AWS (floci) and CI.
